# Лабораторная работа №4
## «Модель доступа Белла-ЛаПадула»

---

## 🎯 1. В чём смысл задачи?

У дискреционной модели (лаба №3) есть дыра: если пользователь **может прочитать** секретный документ
и **может писать** в несекретный, он просто скопирует секрет туда, где его прочитают все.
Матрица доступа это не запрещает: каждое отдельное действие разрешено.

**Модель Белла-ЛаПадулы** (1973, разработана для Минобороны США) — **мандатная** (многоуровневая).
Поверх матрицы прав вводятся **уровни секретности**:

| Уровень | Название |
| :-: | :--- |
| 0 | НЕСЕКРЕТНО |
| 1 | КОНФИДЕНЦИАЛЬНО |
| 2 | СЕКРЕТНО |
| 3 | СОВЕРШЕННО СЕКРЕТНО |

* У каждого **пользователя** — **допуск** (`PrivilegesUser`).
* У каждого **объекта** — **гриф** (`PrivilegesObject`).

Уровни задаются администратором, а не владельцем документа, и пользователь не может их обойти,
даже если ему выдали права в матрице.

### Два главных правила

1. **Простое свойство безопасности — «не читать вверх» (*no read up*).**
   Читать объект можно, только если допуск ≥ грифа: `PrivilegesUser[I] >= PrivilegesObject[J]`.
   Лейтенант не читает документы генерала.

2. **★-свойство — «не писать вниз» (*no write down*).**
   Информация может течь только **вверх** по уровням: из несекретного в секретный — можно,
   из секретного в несекретный — нельзя. Генерал не может (даже случайно) выложить
   секрет в общий документ.

Вместе они гарантируют, что информация **никогда не опускается** на более низкий уровень.
В отличие от HRU, безопасность такой системы **можно доказать** (теорема о базовой безопасности:
если начальное состояние безопасно и каждый переход сохраняет оба свойства, все состояния безопасны).

### Как это реализовано в программе

Буфер обмена — способ показать **поток информации** между объектами. Буфер «помнит» гриф
документа, из которого скопирован текст (`PrivilegesBuffer`).

| Элемент | Условие (по методичке) | Какое правило модели |
| :--- | :--- | :--- |
| Поле **4** — значение видно | `P[I,J] ≠ 0` **и** `PrivilegesUser[I] ≥ PrivilegesObject[J]` | дискреционное право + *no read up* |
| Поле **4** — можно редактировать | дополнительно `P[I,J] = 2` | |
| Кнопка **6** «Копировать» | `PrivilegesUser[I] > PrivilegesObject[J]` | |
| Кнопка **5** «Вставить» | `PrivilegesBuffer < PrivilegesObject[J]` | *no write down*: вставлять только в объект с грифом выше, чем у источника |

«Копировать» берёт выделенный фрагмент (или весь текст, если ничего не выделено).
«Вставить» вставляет в позицию курсора и сохраняет результат в `Object[J]`.

Два уточнения, которых нет в методичке, но без которых модель «протекает»:
* «Вставить» требует ещё и `P[I,J] = 2`: вставка — это модификация объекта.
* Системные **Ctrl+C / Ctrl+X / Ctrl+V** в поле 4 отключены. Иначе секрет можно было бы вынести
  через буфер Windows в обход проверки грифа.

> Неравенства `>` и `<` в методичке **строгие**, поэтому копировать из объекта своего уровня
> и вставлять в объект того же грифа, что у буфера, нельзя. В классической модели там стоит `≤`;
> если преподаватель попросит — поменяйте `pu > po` на `pu >= po` и `PrivilegesBuffer < po`
> на `PrivilegesBuffer <= po` в методе `on_object_selected`.

## 📋 2. Переменные

| Переменная | В методичке | Смысл |
| :--- | :--- | :--- |
| `Users`, `Object`, `P` | те же, что в лабе №3 | пользователи, значения объектов, матрица прав |
| `PrivilegesUser` | `PrivilegesUser[N]` | допуск пользователя (0–3) |
| `PrivilegesObject` | `PrivilegesObject[M]` | гриф объекта (0–3) |
| `buffer_text` | — | текст в буфере программы |
| `PrivilegesBuffer` | `PrivilegesBuffer` | гриф объекта, из которого скопирован текст |

Начальные данные:

| | Допуск | Адм. | Об.1 (гриф 0) | Об.2 (гриф 1) | Об.3 (гриф 2) | Об.4 (гриф 3) |
| :--- | :-: | :-: | :-: | :-: | :-: | :-: |
| Администратор | 3 | 1 | 2 | 2 | 2 | 2 |
| Иванов | 2 | 0 | 2 | 2 | 2 | 1 |
| Петров | 1 | 0 | 1 | 2 | 2 | 0 |
| Сидоров | 0 | 0 | 2 | 1 | 0 | 0 |

### Сценарий для защиты
1. **Иванов → Объект 4.** В матрице у него есть право чтения (`P = 1`), но допуск 2 < гриф 3 —
   **доступ запрещён**. Мандатное правило сильнее дискреционного.
2. **Петров → Объект 3.** `P = 2`, но допуск 1 < гриф 2 — тоже запрещено.
3. **Иванов → Объект 2** (гриф 1) → «Копировать». Буфер получает гриф 1.
4. **Иванов → Объект 3** (гриф 2) → «Вставить» **активна**: 1 < 2, информация идёт вверх.
5. **Иванов → Объект 1** (гриф 0) → «Вставить» **неактивна**: 1 < 0 неверно — запись вниз запрещена,
   хотя `P = 2` и редактировать объект Иванов может.
